Вот моя оперативная выжимка и первые критические замечания для Гриши:

#### 1. Где закопан главный скелет: Изоморфный мост вместо поломки React (`#скелет`)
Гриша, в текущем Hermes Desktop React-рендерер плотно завязан на `window.electronAPI`. Если мы начнём рефакторить компоненты чата под `invoke()` из Tauri, мы получим вечный мердж-конфликт с апстримом Nous Research.
**Моё предложение**: написать модуль `desktop-bridge.ts`, который внутри WebView эмулирует сигнатуры `window.electronAPI`, но под капотом аккуратно вызывает команды Tauri. Тогда React UI останется девственно чистым, и мы сможем в любой момент обновлять рендерер из официального репозитория Hermes без боли.

#### 2. Процессы-зомби Python Gateway (`#риск`)
Гриша, ты знаешь, как капризен Python при внезапном закрытии окон. Если пользователь закроет крестик окна Tauri, а `hermes serve` останется крутиться в памяти — база `~/.hermes/sessions.db` окажется заблокирована SQLite, а порты будут заняты. 
В Rust нужно сразу заложить RAII-обертку:
- На Windows: Win32 Job Objects с флагом автоуничтожения дочерних процессов.
- На Linux/macOS: перехват `tauri::RunEvent::Exit` + graceful shutdown с отправкой сигнала SIGTERM и фоллбэком на SIGKILL.

#### 3. Pake vs Чистый Tauri v2 (`#решение`)
Pake хорош для сайтов, но Hermes Desktop — это полноценное рабочее место с хоткеями, системным треем, локальным выбором директорий и drag-and-drop файлов. Давайте не застревать на ограничениях `pake-cli`, а сразу строить чистый проект Tauri v2 с проверенными плагинами (`shell`, `dialog`, `fs`, `notification`, `global-shortcut`).
