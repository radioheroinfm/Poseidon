Вот моя оперативная выжимка и первые критические замечания для Гриши:

#### 1. Где закопан главный скелет: Изоморфный мост вместо поломки React (`#скелет`)
Гриша, в текущем Hermes Desktop React-рендерер плотно завязан на `window.electronAPI`. Если мы начнём рефакторить компоненты чата под `invoke()` из Tauri, мы получим вечный мердж-конфликт с апстримом Nous Research.
**Моё предложение**: написать модуль `desktop-bridge.ts`, который внутри WebView эмулирует сигнатуры `window.electronAPI`, но под капотом аккуратно вызывает команды Tauri. Тогда React UI останется девственно чистым, и мы сможем в любой момент обновлять рендерер из официального репозитория Hermes без боли.

#### 2. Процессы-зомби Python Gateway (`#риск`)
Гриша, ты знаешь, как капризен Python при внезапном закрытии окон. Если пользователь закроет крестик окна Tauri, а `hermes serve` останется крутиться в памяти — база `~/.hermes/sessions.db` окажется заблокирована SQLite, а порты будут заняты. 
В Rust нужно сразу заложить RAII-обертку:
- На Windows: Win32 Job Objects с флагом автоуничтожения дочерних процессов.
- На Linux/macOS: перехват `tauri::RunEvent::Exit` + graceful shutdown с отправкой сигнала SIGTERM и фоллбэком на SIGKILL.

#### 3. Pake vs Чистый Tauri v2 (`#решение`)
Pake хорош для сайтов, но Hermes Desktop — это полноценное рабочее место с хоткеями, системным треем, локальным выбором директорий и drag-and-drop файлов. Давайте не застревать на ограничениях `pake-cli`, а сразу строить чистый проект Tauri v2 с проверенными плагинами (`shell`, `dialog`, `fs`, `notification`, `global-shortcut`).

#### 4. Анекдот в тему (`#юмор`)

**Скелеты, до которых докопался:**

1. `#скелет` **Убийство шлюза при закрытии окна ломает наш же инвариант.** По ARCHITECTURE.md шлюз один на машину и владеет всеми сессиями, а CLI, боты и cron — его клиенты. Если Tauri при выходе делает SIGTERM/JobObject на шлюз, мы роняем чужие сессии. Нужна политика владения: убиваем только тот шлюз, который запустили сами, иначе просто подключаемся (attach).
2. `#скелет` **Метрика «5–15 МБ против 150–400 МБ» нечестная.** Мы сравниваем голую оболочку с полным дистрибутивом. Если бандл везёт Python-рантайм, он и даст основной вес. Нужны две цифры: «оболочка» и «оболочка + рантайм».
3. `#скелет` **Статусы «Audited» и «Phase 0 — 100%» без доказательств.** Нет версий и хэшей апстрима, на котором делался разбор. Предлагаю закрепить в ARCHITECTURE.md версию и коммит Hermes, по которым всё написано.
4. `#скелет` **Симулятор в `workspace/`.** Консоль отвечает захардкоженными значениями (PID, порт, «Python 3.14 found»). Заголовок помечен «Emulated», но стартовые строки выглядят как реальные результаты. Прошу `[SIM]` на каждой строке. И `package.json` называется `react-example` — переименовать.
5. `#скелет` **Мелкие противоречия.** ADR-001…003 — одни заголовки без обоснований; нет файла LICENSE при заявленной MIT; «два брата» в преамбуле, а нас три; «никто никому не начальник», но в README у Гриши «Руководитель», а в дашборде Женя «выполняет команды Гриши». Давайте выберем одну формулировку.

**Новая вводная от Толяна.** Его конечная цель — переписать на Rust **всё, что получится**, но постепенно. Значит, Tauri-оболочка — первый кирпич, а не финал. Предлагаю такие ADR:

- **ADR-006: стратегия «душителя».** Формализуем протокол шлюза (JSON-RPC/WebSocket) как версионированный контракт. Любой компонент Python заменяется на Rust за тем же интерфейсом.
- **ADR-007: тесты паритета до кода.** Прежде чем переписывать модуль, фиксируем эталонное поведение Python-версии и гоняем одни и те же сценарии против обеих реализаций.
