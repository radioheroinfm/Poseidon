## 3. Находки

### 🔴 R1. Гонка: владение шлюзом записывается только после ожидания READY `[ПРОЧИТАНО]`
В `GatewayManager::start()` порядок такой: `spawn` → поток-дренажёр → **ждём READY до 60 с** → только потом **фаза C**: `*child_guard = Some(child); *owned_guard = true`. Всё это время `child = None` и `owned = false`.
Последствия:
- Пользователь закрывает окно (или нажимает «Выйти») во время холодного старта. `RunEvent::Exit` → `stop()` видит «не наше» и **ничего не делает**. Шлюз остаётся жить сиротой, и это ровно тот зомби-сценарий, ради которого придумана вся политика владения.
- Женя в §6 Отчёта №4 назвал это «редким окном». Я не согласен: по вашим же данным окно равно холодному старту, **30–60 секунд**, и именно в нём пользователь чаще всего нервничает и закрывает приложение. Рабочий приоритет: чинить до закрытия эпохи.
- Смежное: если процесс умер до READY (поток stdout закончился → `Disconnected`), код всё равно кладёт мёртвого «ребёнка» в состояние и возвращает `running: true, owned_by_us: true, "still starting?"`. Это неверное состояние, причина смерти не видна (stderr в `null`).
**Фикс (набросок, не компилировал)**:
```rust
let mut child = cmd.spawn()?;
let pid = child.id();
let stdout = child.stdout.take();
{   // владение фиксируем СРАЗУ после spawn, до любого ожидания
    let mut c = self.child.lock().map_err(|e| e.to_string())?;
    let mut o = self.owned_by_us.lock().map_err(|e| e.to_string())?;
    *c = Some(child);
    *o = true;
}
// ... поток-дренажёр над `stdout`, rx.recv_timeout(READY_TIMEOUT) без блокировок ...

// после ожидания проверяем, жив ли процесс
let alive = {
    let mut c = self.child.lock().map_err(|e| e.to_string())?;
    matches!(c.as_mut().map(|ch| ch.try_wait()), Some(Ok(None)))
};
if !alive {
    *self.child.lock().map_err(|e| e.to_string())? = None;
    *self.owned_by_us.lock().map_err(|e| e.to_string())? = false;
    return Ok(/* running:false, message: "hermes exited before READY" + код выхода */);
}
```
И тест: фиктивный «шлюз» (скрипт, который 3 секунды молчит, потом печатает READY), в середине ожидания вызываем `stop()`, дочерний процесс должен умереть.

### 🔴 R2. ADR-012 не выполнен, а документы говорят, что выполнен `[ПРОЧИТАНО]`
- CI-файл в `docs/ci/github-actions-ci.yml`, а GitHub читает только `.github/workflows/`. Причина честно описана в `BUILD.md` (у PAT нет scope `workflow`). Это нормально. Ненормально, что `MIGRATION_PLAN.md` ставит `[x] GitHub Actions … workflow добавлен`. Пока workflow не запущен, галочки нет.
- **Лок-файлов нет.** `Cargo.lock` не закоммичен (в плане «появится после первой сборки», но он не появился в репо). `.gitignore` прямо игнорирует `package-lock.json`. Для приложения оба файла нужно коммитить, иначе сборка не воспроизводится, а CI-шаг `npm install` каждый раз резолвит версии заново (должен быть `npm ci`).
- В CI нет `cargo clippy -- -D warnings`; `cargo fmt --check || true` «информационный» (допустимо, но тогда заведите задачу на его включение).
- **Решение**: Толян копирует файл в `.github/workflows/ci.yml` руками через UI (как и написано в BUILD.md), добавьте `Swatinem/rust-cache`, `npm ci`, clippy; закоммитьте оба lock-файла и уберите `package-lock.json` из `.gitignore`. Пока CI не зелёный на трёх ОС, эпоха открыта, это ваш же ADR-012.

### 🟠 R3. Обнаружение шлюза: фиксированный порт против динамического `[ПРОЧИТАНО]` + `[НЕ ПРОВЕРЕНО]`
Вы сами записали в `FINDINGS`: «порт не зафиксирован как 8642, он анонсируется процессом». Но `GatewayManager` при старте проверяет **только `DEFAULT_GATEWAY_PORT = 8642`** и считает «открытый порт» признаком «наш шлюз уже работает». Следствия:
1. Если у пользователя шлюз уже запущен (CLI, бот, cron) на другом порту, Poseidon **его не найдёт и поднимет второй**. Это нарушает инвариант «один шлюз на машину» из ARCHITECTURE.md и может задвоить сессии и ботов.
2. Если на 8642 сидит чужой процесс, мы к нему «подключимся».
3. `getGatewayWsUrl` в апстримном `preload.ts` намекает на то, что рендерер получает готовый WebSocket-URL, возможно с токеном. Если у шлюза есть авторизация, то «attach» без знания токена просто не сработает.
**Вопросы к апстриму (отвечает Гриша по своему локальному клону)**: (а) как остальные клиенты (CLI, боты, Electron main) находят уже запущенный шлюз: lock/PID/port-файл в `~/.hermes`, переменная окружения? (б) отказывается ли второй `hermes serve` запуститься, если первый уже есть? (в) откуда Electron main берёт WS-URL и токен? (г) как рендерер аутентифицируется? От ответов зависит вся механика attach.
**Фикс после ответов**: discovery по тому же механизму, что у апстрима; handshake (имя, версия протокола); статус `PortOccupiedByForeign`; порт всегда из анонса или из файла, не из константы.

### 🟠 R4. Мост и ADR-007: предпосылка изменилась `[ПРОЧИТАНО]` + `[НЕ ПРОВЕРЕНО]`
ADR-007 обещал: «React-рендерер Hermes остаётся нетронутым, мост прикидывается `electronAPI`». Теперь известно:
- Рендерер говорит с `window.hermesDesktop` (~166 ключей верхнего уровня, вложенные `windowControls.{minimize,toggleMaximize,close,custom}` и т. д.).
- Наш `PoseidonDesktopAPI` плоский и **придуман нами** (`windowMinimize()`, `gatewayStart()`…): имена не из апстрима. Женя уже указал: `hermesDesktop.windowControls.minimize` даст `undefined`, а `index.ts` ставит `window.hermesDesktop = api` с плоскими методами.
- Мост **не попадает в бандл**: `frontendDist` указывает на статичный placeholder, сборка фронта не настроена. Кнопки в окне будут показывать «Bridge not installed».
- Типично для Electron-приложений основная работа лежит не в `preload.ts` (он только пробрасывает `ipcRenderer.invoke`), а в **обработчиках главного процесса**. Для Hermes это `[НЕ ПРОВЕРЕНО]`, но проверить легко (см. вопросы ниже). Если это так, настоящий объём миграции в разы больше, чем 760 строк preload.
**Рекомендация**:
1. Не расширять текущий API «на глаз». Сгенерировать **карту `docs/upstream/PRELOAD_MAP.md`**: по каждому из ~166 ключей — имя, категория, что делает, какой Electron-API использует в main, чем заменяется в Tauri, объём работы, приоритет (нужен ли для первого запуска UI).
2. Типы `hermesDesktop` **генерировать из `preload.ts` по SHA**, а не писать руками; в CI сравнивать, чтобы расхождение валило сборку.
3. Переписать ADR-007: мост реализует **настоящую форму `hermesDesktop`** (вложенную), поэтапно по приоритетам карты. Плоский `PoseidonDesktopAPI` можно оставить как внутренний слой, но рендерер видит только апстримную форму.
4. Первый честный рубеж Эпохи 3: **настоящий React-рендерер Hermes запускается внутри Tauri и показывает чат, подключившийся к шлюзу**, пусть с заглушками на остальные ключи. Это и есть Spike 1, который я просил в Отчётах №1 и №3. Он сразу покажет реальный объём работы и реальные метрики.

### 🟠 R5. Остановка шлюза: недоделана `[ПРОЧИТАНО]`
- `stop()`: после SIGTERM по группе и паузы вызывается `child.kill()`, а он убивает **только лидера**. Внуки (воркеры Python, процессы инструментов агента) переживут. Нужен `libc::kill(-(pid as i32), libc::SIGKILL)`. Женя поймал это в Отчёте №4 (3c), Гриша не поправил, а итоговое «🟢 ПРИНЯТО» Жени этого пункта не упоминает.
- **Windows**: ничего, ни Job Object (`KILL_ON_JOB_CLOSE`), ни дерева процессов; `find_hermes_binary` знает только unix-пути. Если Windows не цель, запишите это решением в ADR. Если цель, это отдельная задача Эпохи 3.
- **Краш оболочки** (kill -9, диспетчер задач): шлюз осиротеет. Минимум: PID-файл владельного шлюза и «уборка» при следующем запуске; плюс на Linux `PR_SET_PDEATHSIG` (спавнить из выделенного потока, сигнал привязан к потоку-создателю).
- **Слепота**: `stderr` → `Stdio::null()`, stdout только в `debug!`. Если шлюз не поднялся, диагностики нет. Писать оба потока в ротируемый лог-файл в каталоге приложения.
- `status()` всегда возвращает `port: Some(port_now)`, даже когда ничего не запущено (Женя 3b). Контракт в `types.ts` говорит «announced or probed». Верните `None`, когда порт не подтверждён.
- ⚪ Двойная остановка (Exit + Drop) безопасна: после первого `stop()` `owned` сброшен. Оставьте оба.
**Тест на дереве процессов** (Linux, с фиктивным шлюзом, который порождает внука): после `stop()` не должно остаться ни лидера, ни внука.

### 🟠 R6. Безопасность: что осталось после ADR-013 `[ПРОЧИТАНО]` + `[ПРОВЕРИТЬ СБОРКОЙ]`
Хорошо, что ADR-013 называет себя «initial» и честно перечисляет временные решения. Для закрытия эпохи остаётся:
1. **`open_path`**: `file://…` разрешён по построению, нет проверки расширений исполняемых файлов (`.exe`, `.bat`, `.sh`, `.app`, `.lnk`), нет канонизации, UNC-путь `\\server\share\x.exe` проходит (в нём нет `:`). Рендерер, в который просочилась инъекция из вывода модели, всё ещё может «запустить файл».
2. **Права на свои команды (H5)**: `build.rs` не менялся, значит, как я понимаю документацию Tauri v2, `gateway_start`, `open_path` и остальные команды вызываются из любого скрипта WebView вне зависимости от `capabilities/default.json`. Проверить на сборке и описать команды в app manifest.
3. **Лишний `shell:allow-open`**: плагин shell не используется (команды идут через крейт `open`), а permission открыт. Либо убрать плагин и permission, либо перейти на плагин как на единственный путь.
4. **CSP**: `'unsafe-inline'` в `script-src`, `withGlobalTauri: true`, wildcard-порты `127.0.0.1:*` и `localhost:*`. Теперь, когда порт известен из READY, можно сделать `connect-src` с конкретным портом: прописывать его при старте окна (динамический CSP через конфиг окна) либо проксировать через IPC.
5. `open::that(&url)` получает **нетримленную** строку (проверка идёт по `trim()`), мелочь: передавайте то, что проверили.
Это не блокеры Эпохи 2, но **каждый пункт должен остаться в чек-листе с владельцем и сроком**, а не раствориться.

### 🟡 R7. `rust-version = "1.75"` `[ПРОЧИТАНО]`
Изначально стояло 1.85; при подгонке под среду агента поле понизили до 1.75. `BUILD.md` сам говорит, что на 1.75 не собирается из-за `edition2024` у транзитивных крейтов; Tauri 2 требует свежего Rust. Поле `rust-version` описывает требование проекта, а не возможности окружения. Верните 1.85, а проблему окружения агента решайте окружением. Заодно: `libc` нужен только под `cfg(unix)`, вынесите в `[target.'cfg(unix)'.dependencies]`.

### 🟡 R8. Иконки `[ПРОЧИТАНО]` + `[ПРОВЕРИТЬ СБОРКОЙ]`
`icon.icns` весит 8 байт (пустой контейнер), в `icon.ico` заголовок записи заявляет 256×256, а внутри PNG 128×128. На Linux незаметно, на macOS/Windows упаковка может упасть или дать кривую иконку. Лечение в вашей же README: `npm exec tauri icon <source.png>` (исходник, судя по Жене, уже лежит в `assets/`). Сгенерировать и закоммитить полный набор.

### 🟡 R9. Диалоги: хвосты `[ПРОЧИТАНО]`
`filters` по-прежнему отсутствуют в Rust-структурах (молча отбрасываются). Save-`defaultPath` целиком уходит в `set_file_name` (полный путь надо разделить на каталог и имя). `blocking_*` диалоги выполняются в async-пуле, оберните в `spawn_blocking`.

### 🟡 R10. Тесты: количество есть, охвата нет `[ПРОЧИТАНО]`

Нет контрактного теста Rust↔TS (общий JSON-фикстюр), нет теста таблицы платформ, нет TS-тестов. ### ⚪ R12. Вес репозитория
