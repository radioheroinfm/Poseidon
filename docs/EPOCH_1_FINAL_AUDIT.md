## 3. Фокусы внимания для стратегического аудитора (Коляна)

### 🔍 1. Диалоги: выбор директории проекта vs выбор файла
В `src-tauri/src/bridge.rs` Гриша подключил `tauri-plugin-dialog` и написал метод `show_open_dialog`:
```rust
let mut builder = app.dialog().file();
...
let result = builder.blocking_pick_file();
```
*Замечание Жени*: В оригинальном Hermes Desktop пользователь чаще всего выбирает **папку рабочего пространства** (`openDirectory`), а не отдельный файл. Гриша честно пометил: `// Упрощённо: один файл. multiple/directory можно расширить позже`. Колян, оцени с высоты стратегии: стоит ли поддержать `pick_folder()` отдельным флагом уже на старте Эпохи 2?

### 🔍 2. Определение PID чужого Gateway в attach-режиме
В `gateway.rs` при обнаружении открытого порта 8642 (`is_port_open()`) возвращается:
```rust
GatewayStatus { running: true, pid: None, owned_by_us: false, port_open: true, ... }
```
`pid: None` — это абсолютно честно, так как из TCP-хэндшейка PID процесса не очевиден без сканирования системных сокетов (`lsof` / `netstat` / `/proc/net/tcp`). Нужно ли нам в будущем вычислять PID чужого процесса или `pid: None` при `owned_by_us: false` — это достаточный и безопасный контракт?

### 🔍 3. Асинхронность и блокировки в командах Tauri
В `bridge.rs` команды объявлены как `pub async fn`, но внутри вызывают `state.lock()` синхронного `std::sync::Mutex`. В `gateway_start()` есть `std::thread::sleep(400ms)`. Гриша держит мьютекс внутри менеджера. Посмотри, стоит ли в Эпохе 2 перевести `GatewayManager` на `tokio::sync::Mutex` или вынести запуск в фоновый `tokio::task::spawn_blocking`.

### 🔍 4. Безопасность и CSP
Директива CSP открыта для `ws://127.0.0.1:*` и `http://127.0.0.1:*`. Проверь, нет ли риска подмены ответов при многопользовательском окружении на одной машине.
