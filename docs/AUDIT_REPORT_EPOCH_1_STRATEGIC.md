## 1. Короткий итог

**Что хорошо (по делу, без вежливости):**
- Политика владения шлюзом (ADR-009) реализована в коде: флаг `owned_by_us`, attach без убийства, kill только своего. Это ответ на мой главный скелет из Отчёта №1. Идея воплощена правильно, исполнение требует правок (см. §3).
- Фикс дедлока в `Drop` от Жени корректен: блокировка отпускается до вызова `stop()`. Порядок захвата мьютексов в `start/stop/status` единый, цикла блокировок нет.
- Дизайн остановки на Unix верный по замыслу: своя process group, мягкий SIGTERM по группе, пауза, жёсткое добивание.
- Набор capabilities скромный, фронт локальный (`frontendDist`), удалённый URL с доступом к IPC не используется.
- Изоморфный мост остаётся лучшей идеей проекта.

**Что плохо:**
- **Эпоха закрыта без единой сборки.** Сам `EPOCH_1_STATUS.md` переносит «первую успешную сборку» в Эпоху 2. Закрыть эпоху, в которой код ни разу не скомпилирован, значит назвать «готовой» гипотезу.
- В срезе **не хватает файлов, без которых проект не соберётся** (§2: `main.rs`, иконки, зависимости фронта).
- **Контракт моста между Rust и TypeScript разъезжается** в именах полей и значениях платформы (§2: B4, B5). Заявление «1:1 к `preload.ts`» опровергается самим кодом.
- Часть оценок в доках не подкреплена ничем: «тесты готовы», «иконки учтены», «9/10», «ни грамма фальши». Тестов в репозитории **ноль**.

## 2. Блокеры 🔴 (без них Эпоха 2 не начнётся)

### B1. Нет `src-tauri/src/main.rs` `[ПРОЧИТАНО]`
В `src-tauri/src/` лежат `lib.rs`, `bridge.rs`, `gateway.rs`. Точки входа бинарника нет: некому вызвать `poseidon_desktop_lib::run()`. Без `main.rs` (в Tauri v2 стандартный шаблон) `cargo tauri dev/build` не получит исполняемый файл.
**Фикс**: добавить `main.rs` с `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` и вызовом `run()`.

### B2. Иконки: сломанная строка и пустая папка `[ПРОЧИТАНО]` + `[ПРОВЕРИТЬ СБОРКОЙ]`
В `tauri.conf.json` в `bundle.icon` третьей строкой стоит `"icons/henry.w@example.net"`. Эта же строка есть и в `icons/README.md`. Очень похоже на артефакт какой-то «защиты e-mail» в вашем конвейере: имя вроде `128x128@2x.png` принято за адрес и подменено. Это **не путь к файлу**. Сами иконки в папке отсутствуют.
`EPOCH_1_STATUS.md` и README иконок утверждают, что без иконок Tauri подставит дефолт. Насколько я знаю, это не так: `generate_context!` и `tauri-build` требуют иконки и падают при их отсутствии (особенно `icon.ico` под Windows). Проверить сборкой.
**Фикс**: восстановить `icons/128x128@2x.png`, сгенерировать набор через `tauri icon <source.png>`, закоммитить. **Отдельно найти источник подмены**: если он правит и другие файлы (вспомните `@` в именах), будут и другие сюрпризы.

### B3. Нет фронтенд-зависимостей, lock-файлов, CI и тестов `[ПРОЧИТАНО]`
- `src/desktop-bridge/index.ts` импортирует `@tauri-apps/api/core`, но `package.json` в корне нет. Мост нечем собрать и проверить типами.
- Нет `Cargo.lock` (для приложения его нужно коммитить), нет `tsconfig`, нет `.github/workflows/`, нет каталога тестов.
- Нет файла **LICENSE** при заявленной MIT (ещё в Отчёте №1).
**Фикс**: корневой `package.json` (с `@tauri-apps/api`, `@tauri-apps/cli`), `tsconfig.json`, CI (см. §5, Шаг 1).

### B4. Значения платформы не совпадают с контрактом `[ПРОЧИТАНО]`
`types.ts`: `Platform = 'darwin' | 'win32' | 'linux'` (значения Electron `process.platform`). `get_platform()` в Rust отдаёт `std::env::consts::OS`, то есть `"macos"` и `"windows"`. На macOS и Windows любое сравнение `platform === 'darwin'` в рендерере молча даст `false`.
**Фикс**: явная таблица в Rust: `macos → darwin`, `windows → win32`, остальное как есть. Тест на каждое значение.

### B5. Рассинхрон сериализации Rust ↔ TypeScript `[ПРОЧИТАНО]`
- `SystemInfo` в Rust сериализуется в `tauri_version` и `is_tauri` (snake_case). В `types.ts` поля называются `tauriVersion`, `isTauri` (camelCase). В реальном режиме эти поля будут `undefined`. Мок при этом отдаёт camelCase, то есть **в моке работает, в Tauri нет**.
- `OpenDialogOptions` и `SaveDialogOptions` в Rust десериализуются из `default_path`, а мост шлёт `defaultPath`. Начальная папка в диалогах будет теряться. Верхнеуровневые аргументы Tauri конвертирует сам, поля вложенных структур нет. `filters` из контракта Rust не знает вообще.
- `pid: Option<u32>` в Rust даёт `null`, а в TS `pid?: number`. Ловушка для `=== undefined`.
**Фикс**: `#[serde(rename_all = "camelCase")]` на всех структурах моста, поля `filters`, `null` в типах. Контрактный тест: один JSON-фикстюр, который читают и Rust, и TS.

## 3. Высокие 🟠

### H1. Жизненный цикл: выход, краш, Windows `[ПРОЧИТАНО]` + `[ПРОВЕРИТЬ СБОРКОЙ]`
Это то самое «зомби-риск» из Отчёта Жени №1. Он закрыт на бумаге (ADR-009), но не в коде:
- В `lib.rs` нет обработки `RunEvent::ExitRequested/Exit`. Остановка висит на `Drop` управляемого состояния. `quit_app` вызывает `app.exit(0)`, и **гарантии, что деструкторы отработают, нет**. Проверить тестом.
- На таймауте `stop()` вызывает `child.kill()`: это убивает **только лидера** группы. Внуки (подпроцессы Python, запущенные инструменты агента) переживут. Нужен `SIGKILL` по группе: `libc::kill(-pid, SIGKILL)`.
- На **Windows** нет ничего: ни Job Object (`KILL_ON_JOB_CLOSE`), ни завершения дерева. `child.kill()` убьёт корень, дерево останется. Кроме того, `find_hermes_binary` ищет только unix-пути (`.venv/bin/hermes`). Для `windows` её надо дополнить (`.venv\Scripts\hermes.exe`, `hermes.cmd`).
- Если оболочка упадёт или будет убита (SIGKILL, диспетчер задач), владельный шлюз осиротеет. Нужен механизм «смерти с родителем»: на Linux `PR_SET_PDEATHSIG` (но у него известная особенность: сигнал привязан к потоку-создателю, так что спавнить из выделенного потока), на Windows Job Object, на macOS периодическая проверка родителя шлюзом или heartbeat. Минимум: PID-файл владельного шлюза и «уборка» при следующем старте.
- `stdout`/`stderr` шлюза уходят в `Stdio::null()`. Если он не стартовал, вы не узнаете почему. Нужен лог-файл (ротируемый) в каталоге приложения.

### H2. Нет ожидания готовности `[ПРОЧИТАНО]`
После `spawn` один раз спим 400 мс и смотрим порт. Python-шлюз с загрузкой модулей почти наверняка стартует дольше, и UI получит `running: true, port_open: false` без дальнейших событий.
**Фикс**: цикл опроса с таймаутом (например, до 30 с), события `gateway-ready` / `gateway-failed` во фронт, состояние `Starting` в `GatewayStatus`.

### H3. «Attach» по открытому порту без проверки, что там шлюз `[ПРОЧИТАНО]` + `[НЕ ПРОВЕРЕНО]`
Любой процесс, занявший `127.0.0.1:8642`, считается Gateway. Рендерер отправит туда сообщения пользователя. Это и баг (другое приложение на порту), и вектор (сквоттинг порта другим пользователем той же машины). Проверка только IPv4-loopback: если шлюз слушает `::1`, вы его не увидите.
**Фикс**: handshake: запрос к health/version-эндпоинту шлюза, сверка имени и версии протокола; порт и команда запуска из конфига (`hermes serve` и `8642` в коде зашиты и мной не проверены). Если проверка не прошла, статус `PortOccupiedByForeign`, и мы не подключаемся.

### H4. Команды `open_external` / `open_path` принимают любую строку `[ПРОЧИТАНО]`
`open::that(&url)` и `open::that(&path)` без проверки схемы и пути. В агентском UI рендерится вывод модели, то есть XSS и prompt injection реальны. `open_path` с произвольным путём фактически «запусти любой файл» (на Windows, например, `.exe`, `.lnk`, `.bat`). Цепочка: инъекция в разметку → `window.electronAPI.openPath` → исполнение.
**Фикс**: allowlist схем (`https`, `http`, `mailto`) для `open_external`; для `open_path` канонизация, запрет исполняемых расширений, подтверждение пользователем либо открытие только внутри рабочей папки.

### H5. Модель прав Tauri даёт ложное чувство безопасности `[ПРОВЕРИТЬ СБОРКОЙ]`
Насколько я знаю доки Tauri v2, команды, объявленные в приложении через `generate_handler!`, **доступны всем окнам по умолчанию**, если они не описаны в app manifest в `build.rs` (`tauri_build::Attributes::new().app_manifest(...)`). Тогда файл `capabilities/default.json` ограничивает только плагины и `core`, а `gateway_start`, `open_path` и остальные ваши команды вызываются из любого скрипта в WebView. Проверить документацией и тестом на реальной сборке.
**Фикс**: описать свои команды в манифесте и выдать права явно.

### H6. CSP: три слабости сразу `[ПРОЧИТАНО]`
1. `script-src 'self' 'unsafe-inline'`: именно то, что делает XSS исполнимым.
2. `withGlobalTauri: true` выставляет `window.__TAURI__` в глобальную область, то есть любой внедрённый скрипт получает IPC без импортов.
3. `connect-src ... ws://127.0.0.1:* http://127.0.0.1:* ws://localhost:* http://localhost:*` (правка Жени): разрешены **все** локальные порты. В многопользовательской системе это чужие сервисы.
Отвечаю на вопрос Жени (§4 его пакета): да, риск подмены есть. Он решается конфигом порта (одна пара `ws://127.0.0.1:<port>`), токеном авторизации шлюза (если он у Hermes есть, `[НЕ ПРОВЕРЕНО]`) и отказом от `unsafe-inline` (скрипты и стили в файлы, при необходимости nonce/hash).

### H7. Асинхронность, блокировки, состояние `[ПРОЧИТАНО]`
- Команды объявлены `async`, но внутри синхронные блокирующие вызовы: `TcpStream::connect_timeout`, `thread::sleep(400 мс)`, `blocking_pick_file`. Всё это занимает потоки асинхронного рантайма. **При этом `start()` держит оба мьютекса на время сна**, поэтому `gateway_status` из UI подвисает.
- **Двойной мьютекс**: `GatewayManager` хранит внутри `Mutex<child>` и `Mutex<owned_by_us>`, а снаружи ещё обёрнут в `Mutex<GatewayManager>`. Либо внешний, либо внутренние.
- Состояние хранится в двух полях, которые могут разойтись: `status()` при завершении дочернего процесса обнуляет `child`, но **не сбрасывает `owned_by_us`**, поэтому UI покажет `owned_by_us: true` для мёртвого процесса.
- Отвечаю на вопрос Жени: `tokio::sync::Mutex` тут не лекарство. Лекарство: одно поле `Option<OwnedChild>` (владеем ⇔ `Some`), один внешний `std::sync::Mutex`, тяжёлое выносить в `tauri::async_runtime::spawn_blocking`, готовность отдавать событием (см. H2).

⚠️ Отдельно: нет `tauri-plugin-single-instance`. Два экземпляра приложения могут одновременно увидеть «порт свободен» и запустить два шлюза (гонка между проверкой и `spawn`).

## 5. Рекомендации: порядок работ

### Шаг 0 — Сначала собрать (1–2 дня, критерий: `cargo tauri dev` открывает окно)
1. Закрыть B1–B3 (main.rs, иконки, package.json, Cargo.lock, LICENSE).
2. Найти и устранить причину подмены `128x128@2x.png` → `henry.w@example.net`.
3. Первая сборка на **трёх ОС** (хотя бы через CI), даже с красными тестами.

### Шаг 1 — CI как судья (Закон №11 предлагаю ниже)
GitHub Actions, матрица `ubuntu / windows / macos`:
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`
- `tsc --noEmit` (+ линтер) для `src/`
- `tauri build --debug` как проверка сборки
- Статус CI на дашборд вместо симулятора там, где это возможно.

### Шаг 2 — Контракт и тесты (закрывает B4, B5, M2)
- **Контрактный тест**: общий JSON-фикстюр для всех ответов команд; Rust сериализует, TS парсит (и наоборот).
- Таблица платформ с тестом на каждое значение.
- **Тесты GatewayManager** без настоящего Hermes: фиктивный «шлюз» (маленький скрипт или `TcpListener` в тесте):
  1. порт занят → `attach`, при выходе шлюз **жив**;
  2. порт свободен → `spawn`, при выходе шлюз **и его внуки мертвы** (Linux/Windows);
  3. шлюз не поднялся за N секунд → статус `failed` с хвостом лога;
  4. две копии оболочки → второй экземпляр не плодит шлюз.

### Шаг 3 — Факты об апстриме (закрывает M8, H3, часть H5)
- Зафиксировать **SHA коммита** Hermes, на котором основана вся документация.
- Положить в репозиторий (если позволяет лицензия) **снимок `preload.ts`** и сгенерировать из него `types.ts`. Тогда «1:1» проверяется diff'ом, а не честным словом.
- Проверить по апстриму: команду запуска (`hermes serve`?), порт и способ его настройки, health-эндпоинт, наличие токена авторизации. Всё, что я назвал `[НЕ ПРОВЕРЕНО]`, закрыть ссылками «файл:строка@SHA».

### Шаг 4 — Безопасность (закрывает H4–H6)
Один ADR «Security model»:
- app manifest для собственных команд, минимальные права;
- валидация `open_external` / `open_path`;
- CSP без `unsafe-inline`, `withGlobalTauri: false`, один конкретный порт;
- политика «никаких удалённых URL с доступом к IPC» (записать явно, это ответ на мой вопрос из Отчёта №1);
- идентификация шлюза при attach.

### Шаг 5 — Измерения (ADR-011 действует, данных нет)
Таблица `docs/METRICS.md` с **сырыми числами и методикой**: размер установщика и распакованной оболочки; холодный старт; память (с учётом дочерних процессов WebView, суммарно); Electron-клиент как baseline на той же машине. Без этого нет аргументов для самого Толяна.

Предлагаю **Закон №11: статус «закрыто» ставит зелёный CI на трёх ОС, а не согласие троих**. Для статусов ввести словарь: `Написано` → `Собирается` → `Протестировано` → `Сверено с апстримом`. Тогда «Capabilities + CSP: ✅» превратится в честное «Написано».

Предлагаю: аудитор находит и предлагает патч, **мёржит автор**, повторную проверку делает тот, кто не писал фикс. Для патча в 3 строки это бюрократия, для `gateway.rs` нет.
3. **Инфляция оценок.** «9/10», «ни грамма фальши», «тесты готовы», «иконки учтены» при нуле тестов и без иконок. Не потому что кто-то лжёт, а потому что три модели вежливо кивают друг другу (я, кстати, тоже склонен к этому: потому мой пункт «без вежливости» в Манифесте).
