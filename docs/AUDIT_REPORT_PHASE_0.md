## 2. Критический разбор и риски

### 🔴 Риск 1: Разрыв контракта между Electron `contextBridge` и Tauri IPC (`#скелет` `#архитектура`)
* **Суть проблемы**: В оригинальном репозитории `hermes-agent/apps/desktop` рендерер React общается с нативной частью через глобальный объект `window.electronAPI` (задаваемый в `preload.ts`). Там десятки методов: `getSystemInfo`, `selectDirectory`, `onWindowMaximized`, `openExternal`, `platform`, `themeSync`.
* **Опасность**: Если Гриша начнёт переписывать вызовы прямо в компонентах React на `invoke('...')` из `@tauri-apps/api`, мы разорвем совместимость с оригинальным рендерером Hermes и лишимся возможности легко подтягивать апдейты из апстрима Nous Research.
* **Решение Жени**: 
  1. Создать легковесный изоморфный слой-адаптер `desktop-bridge.ts`.
  2. Этот слой снаружи выглядит в точности как `window.electronAPI`, но внутри при запуске под Tauri перенаправляет всё на `invoke()` и `listen()`.
  3. UI-компоненты React вообще не должны знать, в каком контейнере они запущены!

---

### 🔴 Риск 2: Процессы-зомби и жизненный цикл Python Gateway (`#риск` `#надежность`)
* **Суть проблемы**: Hermes Gateway — это долгоживущий Python-сервер (`hermes serve`), держащий открытые SQLite-базы, сетевые сокеты и фоновые очереди. В Electron при закрытии окна или крэше процесс часто оставался висеть в фоне и блокировать порты.
* **Опасность**: При перезапуске приложения пользователь получит ошибку `Address already in use` или конфликт блокировок SQLite в `~/.hermes/sessions.db`.
* **Решение Жени**:
  1. В Rust-бэкенде Tauri реализовать RAII-обёртку для дочернего процесса шлюза.
  2. На Windows использовать Win32 `JobObject` (флаг `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`).
  3. На Linux/macOS использовать отправку `SIGTERM` с таймаутом в 3 секунды, после чего делать `SIGKILL`, а также вешать обработчик на событие `tauri::RunEvent::Exit`.
  4. Поддержать флаг `hermes gateway ping` перед попыткой повторного старта.

---

### 🟡 Риск 3: Специфика системного WebView на Linux (WebKitGTK) (`#платформы`)
* **Суть проблемы**: На Windows (WebView2 на Chromium) и macOS (WebKit) системные движки обновляются вместе с ОС и имеют отличную поддержку современного CSS/JS. На Linux WebKitGTK (`libwebkit2gtk-4.1` / `4.0`) часто отстает по фичам, по-другому рендерит скроллбары, веб-шрифты и может конфликтовать с аппаратным ускорением видео/WebGL.
* **Решение Жени**:
  1. Добавить в `MIGRATION_PLAN.md` обязательный тест-сьют для Ubuntu LTS / Fedora.
  2. В CSS Tailwind использовать безопасные фоллбэки для скроллбаров и шрифтовых сглаживаний (`-webkit-font-smoothing: antialiased`).

---

### 🟡 Риск 4: Иллюзия простоты Pake (`#честность`)
* **Суть проблемы**: Pake идеален для того, чтобы за 30 секунд упаковать статический сайт или готовый веб-дашборд в окно WebView. Но Desktop-клиент Hermes требует:
  * Диалоговые окна открытия локальных папок и файлов проекта.
  * Глобальные хоткеи вызова (Spotlight/Raycast-стиль).
  * Трей с контекстным меню и индикатором статуса модели.
  * Drag-and-drop файлов в область промпта.
* **Решение Жени**: Не тратить лишнее время на попытку выжать из `pake-cli` то, для чего он не предназначен. Использовать Pake как ориентир по размеру и флагманам компиляции, но сразу разворачивать проект на **Tauri v2 CLI** (`@tauri-apps/cli`) с официальными плагинами:
  - `tauri-plugin-shell`
  - `tauri-plugin-dialog`
  - `tauri-plugin-fs`
  - `tauri-plugin-notification`
  - `tauri-plugin-global-shortcut`

## 3. Матрица готовности нативных возможностей (Native Capability Matrix)

| **Системный трей** | `new Tray(...)` | `tauri::tray::TrayIconBuilder` | Низкая (2/5) | Меню: Открыть, Статус Gateway, Выход |

| **Буфер обмена (текст + картинки)** | `clipboard.readImage()` | `tauri-plugin-clipboard-manager` | Средняя (2/5) | Проверить вставку скриншотов в чат |

| **Автообновление** | `electron-updater` | `tauri-plugin-updater` | Средняя (3/5) | На этапе Фазы 3 |
